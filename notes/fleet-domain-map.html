One card, round trip

Shuffler: one player's game

Build-up

  • Deck · immutable, with provenance (archidekt, precon, test)
  • GamePrep · a Deck plus sleeve, playmat, table name. Immutable
  • Game · a prep plus its own shuffler event log
  • GameCard · CardDefinition + Location + face + instance id

Shuffler event log kinds

  • start game · deal opening hand
  • shuffle library · mulligan (one atomic event)
  • move card (discard, play face-down, returned)
  • undo

Layers

  • Express routes + HTMX views
  • apply-game-command: load, version check, mutate, persist
  • GameState: the domain
  • Ports with real adapters and fakes: decks, persistence, card cache, images, Spine

Tabletop: the shared room

Shapes

  • mtg-card: instance, scryfall id, face, faceDown, tapped, owner
  • mtg-zone · mtg-counter · mtg-life-counter · mtg-title
  • Counters and notes ride a card as passengers

Gestures

  • tap · drag to zone · flip · turn face-down
  • attach counter or note
  • library portal swallow (the only gesture sent to the Spine so far)
  • every other gesture sent to the Spine as a physical event planned

Identity

  • Room slug is the Spine's table id, opaque
  • Session: ?seat= or an anonymous pseudonym kept in localStorage

Spine: the log

Sender sets

  • id (dedup key) · tableId · name
  • initiator {playerName, seatId?, sessionId?}
  • occurredIn shuffler | tabletop | spine · origin
  • significance physical | domain | administrative
  • schemaVersion · payload

Spine sets

  • seq: the order, unique per table
  • acceptedAt
  • traceparent: attached fresh at broadcast, never stored

Entities

  • Table: slug <name>-<8hex>, unique name
  • Seat: number 1 to 4, keyed by an opaque joinRequestId so join is idempotent
  • Event: one row per envelope

Principles and invariants

Tags say where each one lives: test a test fails if broken · code the code enforces it · stated docs and habit only · planned designed, not built.

Whole fleet

  • Shuffler and Tabletop never talk directly test
  • Events are JSON Schema, validated by sender and receiver code
  • Physics on the Tabletop, meaning in the Interpreter stated
  • Players adjudicate. The app supports play and enforces nothing stated
  • No privileged actor on the canvas stated
  • Playable at all times stated
  • Trace context on every hop; facts go on spans, never addEvent stated
  • Fakes, never mocks stated
  • Corners square except on round things stated

Shuffler

  • A card is in exactly one location code
  • Hidden zones stay hidden; only shadows go public stated
  • State version = shuffler event log length; stale writes get 409 code
  • Everything persisted is versioned; old data fails loudly (HTTP 410) code
  • Decks and preps are immutable code
  • Spine calls are best-effort and never block play code
  • Carry the Spine's ids and URLs; never build them stated
  • A card is played only if the Spine accepted the event first planned

Tabletop

  • The sync server replicates presentation only; it holds no game authority stated
  • A card.played for an unseated player is rejected, not patched over code
  • Duplicate events dropped by event id and instance id code
  • Send-then-commit: a returned card vanishes only after the Spine confirms code
  • Every played card arrives on the Stack code
  • Zones never touch: an empty gap sits between every pair test
  • No persistence yet; the room lives in memory code

Spine

  • One append-only Spine event log per table code
  • The Spine alone assigns seq and acceptedAt code
  • Join is idempotent per joinRequestId code
  • Extra fields allowed, so ships deploy independently code
  • Never replace, supersede planned
  • Visibility on every event, private events cast public shadows planned
  • Provenance and confidence on inferred events planned

Where the story and the code disagree

  • "Best-effort, never blocks play" (code) and "Playable at all times" (stated) are today's rule. The planned rule is the opposite: no Spine, no play.
  • The envelope has no visibility field, and the design summary still says it does.
  • Nothing implements supersede. It is a principle only.
  • The Tabletop's taps, flips and moves reach Honeycomb as spans but never the Spine. They will; shown as planned.
  • table.created is named in docs but has no payload schema and is not sent.
  • The Tabletop's CLAUDE.md says only card.played has a consumer. The dispatch code also handles card.played-face-down, card.discarded and card.returned.
  • The Shuffler's CLAUDE.md names sendCardPlayedToSpineBestEffort. The code calls sendCard{Played,Returned,Discarded}BeforeMutate.
