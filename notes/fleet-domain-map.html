Shuffler: one player's game

The Shuffler also runs alone, with no Table: single-player mode, for people who play on a shared whiteboard like Miro or Mural. The Spine and Tabletop matter only in shared-table games.

Build-up

  • Deck · immutable, with provenance (archidekt, precon, test)
  • GamePrep · a Deck plus sleeve, playmat, table name. Immutable
  • Game · a prep plus its own shuffler event log
  • GameCard · CardDefinition + Location + face + instance id

Shuffler event log, for example

  • start game · deal opening hand
  • shuffle library · mulligan (one atomic event)
  • move card (discard, play face-down, returned)
  • undo

Layers

  • Express routes + HTMX views
  • apply-game-command: load, version check, mutate, persist
  • GameState: the domain
  • Ports with real adapters and fakes: decks, persistence, card cache, images, Spine

Weak spot: the interface layer holds up, but orchestration and domain are not well separated.

Tabletop: the shared gameplay space

The current Tabletop code is a prototype slated for re-implementation. This section describes the intended domain; the vocabulary and the contracts carry over.

Shapes

  • mtg-card: instance, cardDefinitionId, face, faceDown, tapped, owner
  • mtg-zone · mtg-counter · mtg-life-counter · mtg-title
  • Counters and notes ride a card as passengers

Gestures

  • tap · drag to zone · transform · turn face down/up
  • attach counter or note
  • library portal swallow (the only gesture sent to the Spine so far)
  • every other gesture sent to the Spine as a physical event planned

Identity

  • A card's identity rides on its mtg-card shape: instance, cardDefinitionId, owner
  • The Table's URL slug is the Spine's Table id, opaque
  • Session: ?seat= or an anonymous pseudonym kept in localStorage

Spine: the log

Sender sets

  • id (dedup key) · tableId · name
  • initiator {playerName, seatId?, sessionId?}
  • occurredIn shuffler | tabletop | spine · origin
  • significance physical | domain | administrative
  • schemaVersion · payload

Spine sets

  • seq: the order within a Table's log, one counter across every event and seat
  • acceptedAt
  • traceparent, an envelope field, on the way out. In: the sender's trace context rides the HTTP traceparent header, and the Spine ignores any copy in the envelope. Out: SSE has no headers, so the Spine writes its own, a child in the same trace, into the envelope it broadcasts; receivers continue the trace from there. Never stored, so a replay carries none

Entities

  • Table: a unique name and an id, the slug <name>-<8hex>, which is also the Tabletop's URL. Owns one event log and up to four Seats. Creating one appends table.created
  • Seat: a player's place at a Table, numbered 1 to 4 in join order. Holds the player's name. Joining again with the same joinRequestId (the Shuffler sends its game id) gets the same Seat back
  • Event: an envelope the Spine accepted, with its seq. One per sender event id per Table: a resend gets the original back

Translations at the borders

Term Shuffler Tabletop Spine
Game / Seat Game: one player's play session Seat: a player's place at the Table Seat, 1 to 4 per Table. The Shuffler translates Game to Seat at the border and sends its game id as the Spine's opaque joinRequestId
Flip / Transform / Face-down "flip": look at the other printed face; never leaves the Shuffler. Impossible on a one-faced card. Face-down is not modeled "Transform": swap the printed face of a two-faced card, a physical event. Separately, "Turn face down/up": concealment (faceDown on the card shape), on every card card.played-face-down today; Tabletop gestures are not modeled yet
Initiator seatId: the saved state, a player's place at the Table. sessionId: one browser tab, whatever value each ship uses. playerName: for human readability. A Tabletop initiator without a seat is anonymous. Attribution, never authority: there is no permission system. Not the same as a card's owner (whose deck it is in). Validates the wire shape.
Table A card location: the cards on the shared table. The Shuffler tracks that a card is there, never what it does there (tapped, counters, position). The table name is data it carries and never interprets The state of the game. It is represented on the canvas (tldraw's Room). The unit that owns a log

Shuffler

Domain

  • A card is in exactly one location code
  • Decks and preps are immutable code

  • Everything persisted is versioned; old data fails loudly (HTTP 410) code

Tabletop

Domain

  • Every played card arrives on the Stack code

Architecture

  • The sync server replicates presentation only; it holds no game authority stated
  • Duplicate arrivals dropped: by event id, or by the card's instance id (the Shuffler mints one per card at game start) code
  • Send-then-commit: a returned card vanishes only after the Spine confirms code
  • No persistence yet; the Table lives in memory code

Design

  • Zones never touch: an empty gap sits between every pair test

Spine

Domain

  • One append-only Spine event log per Table code

Architecture

  • The Spine alone assigns seq and acceptedAt code
  • Join is idempotent per joinRequestId code
  • Extra fields allowed, so ships deploy independently code

Where the story and the code disagree

  • "Spine calls are best-effort and never block play" is today's rule. The planned rule is the opposite: no Spine, no play on shared-table games.
  • Every join appends both seat.taken (Seat number) and seat.joined (deck, playmat, sleeve, game URL). Only seat.joined has a consumer; the two could fold into one.
  • The Tabletop's taps, transforms and moves reach Honeycomb as spans but never the Spine. They will; shown as planned.
