# A skip-external-content mode: no live Scryfall calls, sized placeholders

Mountain: overhead
Status: wontfix

> _This was generated by AI, recording Jess's words._

## Question

Every page that renders card art or links out (the deck chooser's 191 `<img>` tags, card
modals, anything hitting Scryfall) currently has one mode: reach the live internet or fail/be
slow. Jess wants a second mode — an opt-in the app itself understands, not just a test-only
fake — where:

- No page makes an external network call, ever, while the mode is on.
- Every external image has a fixed-size, decent-looking placeholder instead of nothing/broken.

**Should this live as a real feature on the pages themselves (a URL param or similar), rather
than only as a Playwright-side fake?**

## Why this is not blocked by ticket 03

Ticket 05 gated the "make the deck chooser cheap" work on 03's setup-shape decision, because if
03 seeds games through the API instead of navigating the UI, the verify-suite motive for fixing
the deck chooser mostly evaporates.

This ticket is different: **Jess wants to use this offline, in the running app, not just in
the test suite** — her own words: "it can also help me on airplanes." That's a real use case
independent of how fast `verify.sh` is. So this can be decided and built regardless of what 03
picks. If it lands, it may *also* give 03 and 05 a cheaper option than either "fake
`CardImagesPort` in tests" (03) or "lazy-load images" (05) — a page-level flag that both the
suite and Jess's laptop on a plane can flip.

## Shape, roughly

- A query param or app-wide env/setting (`?offline=1`? a cookie? — Jess's call) that every page
  reads before rendering `<img>` tags pointed at Scryfall, and before any server-side Scryfall
  fetch (`fetchScryfall()` in `src/scryfall-http.ts`, the archidekt adapter's image enrichment).
- A placeholder image: fixed dimensions matching the real art (card art is a known aspect
  ratio), so layout doesn't jump when the flag is off vs on. Needs a design decision, not just
  a gray box — see owners below.
- Decide the boundary: does "external content" mean only Scryfall images, or does it also cover
  Archidekt deck imports (`src/port-deck-retrieval/archidektAdapter/`) and MTGJSON fetches
  (`scripts/fetch-mtgjson-precons.ts`)? Those are already local-file-backed once a deck is
  downloaded (`decks/*.json`), so the live dependency may already be narrower than "every
  external link" suggests — worth checking before designing the flag's scope.

## How this could feed back into 03 / 05

If the flag lands and is good enough, `verify.sh` could just set it for every run — no fake
port, no lazy-loading decision, same mechanism Jess uses on a plane. Re-visit 03 decision 2 and
05 once this exists; don't build a second, test-only version of the same idea in parallel.
